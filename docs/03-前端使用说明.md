# 前端使用说明

> 面向使用者。讲清楚**每个页面是干什么的、每个按钮点了会发生什么、表格里每一列该看什么**。
> 技术实现见 `README.md`，本文只讲怎么用。

---

## 零、先搞清楚这个系统在做什么

一句话：**它帮你先看一遍合同，把可疑的地方标出来，然后写成意见发回审批流程里。**

它不是"合同审批器"，不会替你做"通过 / 驳回"的决定。它只做四件事：

1. 从审批系统把待办的合同**拉过来**；
2. 把合同**读出来**（PDF、Word，连扫描件也能读）；
3. 用 26 条规则**挑毛病**（预付款太高、违约金太高、没有保密条款……）；
4. 把挑出的毛病**整理成一段中文意见**，写回审批单的评论区。

所以你会看到的状态只有"待解析 / 解析中 / 审查中 / 已阻塞 / 已完成"，
**没有"已通过"或"已驳回"**——那一步始终留给人。

## 一、启动

```bash
cd contract_review

# 第一次用（或重装环境后）
uv run --python 3.12 python scripts/make_samples.py   # 生成示例合同
uv run --python 3.12 python scripts/init_db.py        # 建表 + 灌 26 条规则

# 启动页面
uv run --python 3.12 python -m uvicorn app.main:app --port 8080
```

浏览器打开 **http://127.0.0.1:8080**

> 端口被占用？换个端口，比如 `--port 8099`，访问地址也跟着改。
> 若要用命令行做完整演示（不点页面），跑 `scripts/demo_flow.py`。

## 二、页面总览

系统只有 **4 个页面**，顶栏三个链接 + 详情页：

```
┌─────────────────────────────────────────────┐
│ 合同审批审查系统   待办列表 审查规则 运行日志  │ ← 顶栏
└─────────────────────────────────────────────┘

  待办列表 (/)          ← 主入口，所有的活儿从这里开始
  审查规则 (/rules)     ← 看看系统会查哪些毛病
  运行日志 (/logs)      ← 出问题时来这查
  审批详情 (/approvals/{编号})  ← 点"查看详情"进来，干活的地方
```

## 三、待办列表页（首页 `/`）

打开首页就是这里。这是**主入口**。

### 3.1 顶部四个数字卡片

| 卡片 | 含义 |
| --- | --- |
| **任务总数** | 已经从审批系统拉过来多少份合同 |
| **待解析** | 拉过来了但还没开始读的 |
| **已阻塞** | 出问题卡住了、需要人处理的（重点看这个） |
| **已完成** | 审查完并且意见已经写回审批系统的 |

正常流程是：总数不变，**待解析**逐个减少，**已完成**逐个增加。
如果**已阻塞**不为 0，说明有合同处理不了，需要你介入（见第六节）。

### 3.2 「拉取待处理审批单」按钮

这是**第一步操作**，第一次用必须先点它。

点下去会发生：系统去审批系统问"有哪些待我审的合同"，把清单存到本地。
按钮旁边有个「拉取条数」输入框，默认 20，表示这次最多拉多少条。

点完顶部会出现绿色提示：

```
拉取完成：本次共 4 条，新建 4 条，更新 0 条。
```

**怎么看这个提示（很重要）**：

| 情况 | 说明 |
| --- | --- |
| 新建 4 条 / 更新 0 条 | 首次拉取，一切正常 |
| 新建 **0** 条 / 更新 4 条 | **正常现象**。系统按审批编号去重，拉过的不会重复建。你反复点这个按钮，看到的就是这个 |
| 新建 0 / 更新 0 / 共 0 条 | 审批系统里没有待办的合同 |

⚠️ **重点**：点这个按钮**不会**覆盖已有进度。一份已经审查完的合同，
再拉一次也不会被打回"待解析"——这是刻意设计的，防误操作。

### 3.3 待处理审批单表格

一行一个合同。每列含义：

| 列 | 含义 | 该关注什么 |
| --- | --- | --- |
| 审批编号 | 合同的唯一业务编号（如 `HT-2024-0001`） | 跟审批系统里对得上即可 |
| 合同标题 | 合同名称 | — |
| 申请人 | 谁提交的 | — |
| 申请时间 | 什么时候提交的 | — |
| 附件数 | 这份审批单挂了几个文件 | **如果是 0，这份处理不了** |
| 任务状态 | 见下方状态表 | ← **最该看的一列** |
| 回写状态 | 意见有没有写回审批系统 | 见下方 |
| 阻塞原因 | 卡住的技术原因 | 只有"已阻塞"时才有值 |
| 操作 | 「查看详情」按钮 | 点进去干活 |

#### 任务状态（5 种）

| 状态 | 颜色 | 含义 | 你该做什么 |
| --- | --- | --- | --- |
| **待解析** | 灰 | 拉过来了，还没读 | 点进详情 → 一键处理 |
| **解析中** | 蓝 | 正在读文档（扫描件较慢，约 5-7 秒） | 等 |
| **审查中** | 蓝 | 读完了，正在跑规则 | 等 |
| **已阻塞** | 紫 | 卡住了，需要人处理 | **点进去看阻塞原因** |
| **已完成** | 绿 | 全部搞定 | 不用管了 |

#### 回写状态（4 种）

| 状态 | 含义 |
| --- | --- |
| 未回写 | 还没往审批系统写意见 |
| 回写中 | 正在写 |
| 回写成功 | 写进去了，任务到此结束 |
| 回写失败 | 写不进去，任务卡住（会变成"已阻塞"） |

### 3.4 最近运行日志

页面底部，显示最近 20 条系统动作。想看得更全，点顶栏「运行日志」。

## 四、审批详情页（干活的地方）

从首页点「查看详情」进来。**这一个页面包含了全部五个功能区**，从上往下读一遍就完成一次审查。

页面按审查流程排列，顺序是：

```
1. 审批与附件      ← 这是什么合同、有哪些文件
2. 解析结果        ← 系统从合同里读出了什么
3. 规则命中        ← 系统挑出了哪些毛病
4. 结果与回写      ← 最终意见是什么、写回去了没有
5. 全链路日志      ← 每一步发生了什么
```

### 4.1 区块一：审批与附件

**作用**：确认身份 + 看文件。

- **上半部分**是审批基本信息（编号、标题、申请人、时间）和两个状态
- **表单数据**：审批系统里填的字段（部门、金额、对方单位等）
- **附件信息**：每个文件的 `document_id`、文件名、大小、下载状态、SHA256、本地路径

**附件状态怎么看**：

| 下载状态 | 含义 |
| --- | --- |
| 待下载 | 还没下载 |
| 下载成功 | 文件已在本地，可以解析 |
| 下载失败 | 取不到文件 → 会阻塞，下面会显示失败原因 |

**这一区的按钮**（重要，三种情况不同）：

| 任务状态 | 你看到的按钮 | 点了会怎样 |
| --- | --- | --- |
| 待解析 / 解析中 / 审查中 | **一键处理（下载→解析→审查→保存→回写）** | 一条龙全做完，约 7 秒 |
| 已阻塞 | **重新处理** + **重试阻塞任务** | 先点"重试"复位，再点"重新处理" |
| 已完成 | **重新审查（显式允许重处理）** | 见下方警告 |

⚠️ **关于"重新审查"**：任务变成"已完成"后，系统**默认不允许再处理**。
原因有两个：扫描件 OCR 一次要 5-7 秒，白跑很浪费；而且状态会从"已完成"
退回"解析中"，会让人怀疑之前那条意见是不是作废了。

如果合同换版了确实要重审，就点这个按钮（会弹确认框），系统会生成一份**新的**审查意见，
并**再写一条**新的评论到审批系统。

### 4.2 区块二：解析结果

**作用**：让你核对"系统读对了没有"。

上半行是技术信息：解析状态、页数、哪些页走了 OCR、有效字符数、耗时。

下面两张表：

**基础信息表**（8 项）

| 列 | 含义 |
| --- | --- |
| 字段 | 合同标题 / 合同编号 / 签约主体 / 对方名称 / 合同金额 / 币种 / 生效时间 / 到期时间 |
| 值 | 系统读出来的值 |
| 状态 | **已提取** / **提取失败** / **未找到** |
| 位置 | 第几页第几行 |
| 原文片段 | 合同里对应的原话，供你核对 |

**条款信息表**（8 类）

付款、交付、验收、违约、保密、数据、知识产权、争议解决。

每类显示：状态、位置、条款原文（或"未检出"的原因）。

#### 关键理解：`未找到` ≠ 合同没写

这是最容易误读的地方。

| 状态 | 真实含义 | 你该做什么 |
| --- | --- | --- |
| **已提取** | 系统读到了，有值为证 | 核对值对不对 |
| **提取失败** | 找到了相关文字，但没法解析成标准值（比如金额写的是中文大写） | 人工看一眼原文 |
| **未找到** | 系统**没检出** | 人工确认合同里到底有没有 |

**"未找到"只代表系统没找到，不代表合同里没有。** 比如示例合同里
"生效时间"显示未找到，因为原文写的是"自双方盖章之日起生效"——没有具体日期，
系统不会去猜一个。

同理，条款表里如果"保密条款"显示未找到，系统会在下一区报一条"保密条款缺失"的风险。
如果这个判断不对（比如保密内容写在别的条款里），你作为法务可以忽略这条。

### 4.3 区块三：规则命中

**作用**：这是系统的核心产出——**挑出了哪些毛病**。

一条命中一行，五列：

| 列 | 含义 |
| --- | --- |
| 风险 | **高**（红）/ **中**（黄）/ **低**（绿） |
| 规则名称 | 比如"预付款比例过高" |
| 规则编码 | 比如 `R101_ADVANCE_PAYMENT_HIGH`，方便查规则定义 |
| 证据位置 | 第几页第几行 / 全文检索 |
| 命中证据 | **合同里的原话**，或者"检出数值 60%，触发条件 > 30%"这种计算说明 |
| 处理建议 | 该怎么改 |

**举证逻辑**：每条命中都必须给出"为什么"。要么是原文片段，要么是可复现的数值比较。
你可以拿"证据位置"回原文核对——这是设计上刻意保证的，不允许"系统说有风险但说不出依据"。

用示例合同（HT-2024-0001）跑出来是这样的 5 条：

| 风险 | 规则 | 依据 |
| --- | --- | --- |
| 高 | 预付款比例过高 | 检出 60%，触发条件 > 30% |
| 高 | 违约金比例过高 | 检出 30%，触发条件 > 20% |
| 高 | 管辖地约定在对方所在地 | 原文"由乙方所在地人民法院管辖" |
| 中 | 保密条款缺失 | 全文未检出保密条款 |
| 中 | 数据条款缺失 | 全文未检出数据条款 |

### 4.4 区块四：结果与回写

**作用**：看最终意见，把它写回去。

内容依次是：

1. **review_id** + **总风险等级** + 生成时间
2. **中文摘要**：一段话总结整体风险和主要问题
3. **审批关注点**：编号列表，告诉你"需要确认这几件事"
4. **回写内容**：要写进审批系统评论区的完整文本（带 `|` 前缀的框里）
5. **「回写审批评论」按钮**
6. **回写尝试记录**：每次尝试的时间、状态、外部系统返回

#### 关于回写按钮

| 按钮状态 | 说明 |
| --- | --- |
| 可点击「回写审批评论」 | 还没写过，点了会真的写进去 |
| 灰色不可点「已回写成功（重复点击不会重复写入）」 | 已经写过了 |

**重复点击不会产生第二条评论**。这是有意的保护——你手抖点两下，
审批人不会看到两份意见。

如果你确实想让系统再写一次（比如换了审查结果），流程是：
点"重新审查"生成新结果 → 新结果带着新的 `review_id` → 可以再回写一次。

#### 回写尝试记录的读法

正常一条：

```
2026-10-23T05:04:07  回写成功  评论已写入，当前评论数 1
```

如果失败：

```
2026-10-23T05:04:07  回写失败  调用审批系统失败：xxx 超时
```

失败时任务会变成"已阻塞"，重试目标是 `reviewing`（意思是：不用重新读合同，
只要重新写一次就行）。

### 4.5 区块五：全链路日志

**作用**：出问题时查这个。按时间正序，一条一步。

正常一份合同处理完，你会看到这样的序列：

```
[拉取]    新建任务：审批编号 HT-2024-0001，附件 2 个
[下载]    附件下载成功：contract_normal.pdf，3594 字节，SHA256 xxx
[下载]    附件下载成功：contract_scanned.pdf，230978 字节，SHA256 xxx
[解析]    任务状态 pending → parsing：开始解析 2 个附件
[解析]    任务级解析完成：共 2 个附件、2 页、863 字符
[审查]    任务状态 parsing → reviewing：全部附件解析完成
[审查]    审查完成：规则 26 条、命中 5 条、整体风险 high
[结果]    审查结果已保存：review_id=1，评论长度 1325 字符
[回写]    评论回写成功：review_id=1，响应「评论已写入，当前评论数 1」，任务置为 done
```

哪一步停了，问题就在那一步。

## 五、审查规则页（`/rules`）

**作用**：看看系统到底会查哪些毛病。**纯查看，不能改。**

26 条规则，表格列出：优先级、规则编码、规则名称、风险等级、匹配模式、匹配条件、处理建议。

**匹配模式**有三种，理解这个就能理解系统怎么判断的：

| 模式 | 中文名 | 怎么判断 | 例子 |
| --- | --- | --- | --- |
| `threshold` | 阈值比较 | 从原文抽出数字，跟阈值比 | 预付款 60% > 30% → 命中 |
| `keyword` | 关键词匹配 | 指定范围内出现某些词 | 出现"自动续约" → 命中 |
| `missing` | 缺失检测 | 该有的东西没有 | 没有保密条款 → 命中 |

**为什么要看这个页**：
如果某条规则你觉得不合适（比如"违约金超过 20% 就报高风险"对你们行业太严），
可以带着页面上显示的规则编码去找技术人员调整。规则存在数据库里，改起来不难。

## 六、运行日志页（`/logs`）

**作用**：全局视角，最近 300 条日志，按时间倒序。

每行格式：`时间 [阶段] [级别] 任务id 内容`

阶段有：`pull` 拉取 / `download` 下载 / `parse` 解析 / `review` 审查 /
`result` 结果 / `comment` 回写 / `retry` 重试

级别有：`info` 正常 / `warning` 警告 / `error` 错误

**什么时候来这**：
- 想知道刚才点了按钮到底跑了什么
- 全局排查某类问题（比如"最近所有失败是不是都因为附件缺失"）

## 七、一次完整操作流程（照着做）

用示例数据演示一遍，共 4 步：

### 第 1 步：拉取

首页 → 点「**拉取待处理审批单**」

看到绿色提示 `拉取完成：本次共 4 条，新建 4 条`。
四个卡片变成：总数 4 / 待解析 4 / 已阻塞 0 / 已完成 0。

### 第 2 步：处理合同

在表格里找到 `HT-2024-0001  数据治理平台采购合同`，点「**查看详情**」。

进入详情页 → 点「**一键处理（下载→解析→审查→保存→回写）**」。

**等 7 秒左右**（2 个附件里有 1 个扫描件，OCR 比较慢）。
页面会自动刷新，顶部出现绿色提示：

```
处理完成。review_id=1  回写状态：success
```

### 第 3 步：看结果

刷新后的详情页，从上往下：

1. 任务状态变成 **已完成**（绿色），回写状态 **回写成功**
2. 解析结果：8 项基础信息大部分是"已提取"，保密/数据条款是"未找到"
3. 规则命中：**5 条**，3 条高风险 + 2 条中风险
4. 结果与回写：总风险等级 **高**，5 条审批关注点，回写内容一整段中文意见
5. 回写按钮变成灰色"已回写成功"

### 第 4 步：验证幂等（可选但推荐）

再点一次那个灰色按钮——不能点。或者重跑一次流程，你会发现评论区始终只有 1 条意见。

## 八、遇到"已阻塞"怎么办

这是唯一需要你动手处理的情况。分两种：

### 情况 A：附件缺失 / 下载失败

页面上会显示：

```
阻塞原因：attachment_missing
阻塞明细：附件下载失败：审批编号 HT-2024-0003，附件 ATT-0004（contract_missing.pdf），
         原因：附件文件不存在：...\samples\contract_missing.pdf
```

**处理**：这是审批系统那边的问题——记录的附件文件取不到。
需要让对方补传文件。补好之后再点「**重试阻塞任务**」→「**重新处理**」。

### 情况 B：文档内容为空 / 无法识别

```
阻塞原因：document_empty
阻塞明细：文档内容为空：共 1 页（其中视觉空白页 [1]），有效字符仅 0 个（阈值 20）
```

或者：

```
阻塞原因：ocr_unavailable
阻塞明细：第1页未识别到任何文字，可能是空白页或图片无有效内容
```

**处理**：文件本身有问题（空白、太模糊、盖章遮挡）。
让对方提供清晰版本，替换后点「重试阻塞任务」→「重新处理」。

### 情况 C：回写失败

```
阻塞原因：comment_write_failed
重试目标：reviewing
```

**处理**：合同已经读完了、意见也生成了，只是写不回审批系统。
点「重试阻塞任务」，系统会**只重新回写**，不会重新读一遍合同（省时间）。

## 九、常见疑问

**Q：为什么"生效时间"总是显示未找到？**

A：示例合同原文写的是"自双方盖章之日起生效"，没有具体日期。
系统不会猜日期。换成写明了"2024年3月1日生效"的合同就能读出来。

**Q：为什么保密条款显示"未找到"，但我觉得合同里有保密内容？**

A：系统靠两类线索找条款：一是"第X条 保密"这样的标题，二是"保密义务""不得披露"
这类强特征词。如果保密内容散落在其他条款里、且没用这些词，就可能漏检。
这属于**已知局限**，看到"未找到"请人工确认。系统只负责提醒，判断权在你。

**Q：反复点"拉取待办"会不会建一堆重复任务？**

A：不会。系统按审批编号去重，第二次点只会更新信息，`新建` 一定是 0。

**Q：手抖点了两次"回写"，会不会写两条评论？**

A：不会。第二次会直接返回"已写过"，不碰外部系统。

**Q：能不能改规则 / 加规则？**

A：能，但目前不在页面上改（`/rules` 是只读的）。规则存在数据库的 `review_rules`
表里，让技术人员改。加规则就是插一行数据，不用改代码。

**Q：数据存在哪？**

A：`data/contract_review.db`（SQLite 数据库）+ `data/attachments/`（下载的合同文件）。
删掉 `data/` 目录就等于重置系统。

**Q：怎么重置成全新状态？**

A：
```bash
# 停服务后
rm -rf data samples
uv run --python 3.12 python scripts/make_samples.py
uv run --python 3.12 python scripts/init_db.py
```
